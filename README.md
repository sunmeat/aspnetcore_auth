# aspnetcore_auth

Початковий (стартовий) приклад проєкту на автентифікацію користувача в застосунку на **ASP.NET Core** з клієнтом на **React**. На даному етапі реалізовано вхід через **GitHub**, а сам проєкт слугує базою для подальшого розширення функціоналу автентифікації та авторизації.

## Стек технологій

- **Backend:** ASP.NET Core (Web API)
- **Frontend:** React
- **Автентифікація:** OAuth 2.0 (GitHub)

## Структура репозиторію

- `Soccer.Application` — прикладна логіка застосунку
- `Soccer.Common` — спільні утиліти та допоміжні класи
- `Soccer.Domain` — доменні моделі
- `Soccer.Infrastructure` — робота з зовнішніми сервісами та інфраструктурою
- `Soccer.WebAPI` — Web API проєкт, точка входу бекенду
- `react.client` — клієнтський застосунок на React
- `Soccer.sln` — файл рішення для Visual Studio

## Теоретичний блок: що таке OAuth

**OAuth (Open Authorization)** — це відкритий протокол авторизації, який дозволяє застосунку отримати обмежений доступ до ресурсів користувача на іншому сервісі (наприклад, GitHub, Google, Facebook) **без передачі логіна та пароля** цього користувача самому застосунку.

Простими словами: замість того, щоб користувач вводив свій пароль від GitHub безпосередньо у вашому додатку, він переходить на сторінку GitHub, підтверджує там свою особу та дає дозвіл вашому застосунку на доступ до певних даних (наприклад, email чи базового профілю). Після цього GitHub повертає застосунку спеціальний **токен доступу (access token)**, яким і користується застосунок для подальшої взаємодії від імені користувача.

Ключові учасники процесу OAuth:

- **Resource Owner** — власник ресурсу, тобто сам користувач.
- **Client** — застосунок, який запитує доступ (у нашому випадку — наш ASP.NET Core + React проєкт).
- **Authorization Server** — сервер, що видає токени (наприклад, сервер авторизації GitHub).
- **Resource Server** — сервер, де зберігаються дані користувача (API GitHub).

Типовий потік (Authorization Code Flow) виглядає так:

1. Користувач натискає «Увійти через GitHub» на клієнті.
2. Застосунок перенаправляє його на сторінку авторизації GitHub.
3. Користувач підтверджує вхід і надає дозволи (scopes).
4. GitHub перенаправляє користувача назад у застосунок разом з тимчасовим **authorization code**.
5. Бекенд обмінює цей код на **access token**, звертаючись безпосередньо до сервера GitHub.
6. Отриманий токен використовується для отримання даних користувача (наприклад, email, ім'я, аватар) та формування власної сесії/токена в межах застосунку.

Головна перевага OAuth — користувач ніколи не передає свій пароль третьому застосунку, а сам застосунок отримує лише той обсяг доступу, який дозволив користувач.

## Поточна функціональність

- Автентифікація користувача через **GitHub** (OAuth 2.0).

## Плани на розвиток проєкту

Проєкт активно розвивається, і в подальшому планується додати:

- **Захист на стороні бекенду** — перевірка та валідація токенів на серверній частині, захист API-ендпоінтів від неавторизованого доступу.
- **Авторизація через Google-пошту** — додавання ще одного OAuth-провайдера для входу через обліковий запис Google.
- **Авторизація через номер телефону** — реєстрація та вхід за допомогою SMS-коду підтвердження.

## Запуск проєкту

1. Відкрити `Soccer.sln` у Visual Studio (або через `dotnet` CLI).
2. Налаштувати параметри OAuth-застосунку GitHub (Client ID / Client Secret) у конфігурації бекенду.
3. Запустити backend-проєкт `Soccer.WebAPI`.
4. Перейти в директорію `react.client`, встановити залежності (`npm install`) та запустити клієнт (`npm start`).
